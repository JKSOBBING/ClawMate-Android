# ClawMate 共享前端与 Android 架构

主界面与可跨平台业务以锁定的鸿蒙 ArkTS 源码为准。Android 系统能力由 Kotlin 实现，
通过窄接口提供给共享前端；原 Compose 应用保留为回归基线。

## 工程归属

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| `shared-frontend/` | 上游版本锁、共享页面与业务、Android 平台接口、应用组装 | 只读上游输入；不复制 Kotlin 实现 |
| `shared-app/` | ArkUI-X Android 生命周期、权限、桥接和打包 | `:android-capabilities`、锁定 ArkUI-X 运行库 |
| `android-capabilities/` | 两版共用的 Android 本地 OCR、TTS 及能力结果 | Android SDK、ML Kit、协程；不依赖任一应用或 UI |
| `app/` | Compose 基线、其现存数据与尚未抽取的 Android 实现 | `:android-capabilities`；不依赖共享宿主 |

所有 Android 模块由根 `settings.gradle.kts` 管理。共享版不再维护第二套 Gradle 工程入口。
原能力的兼容包名暂时保留，避免无关的调用点重命名；同一能力只有一个实际引擎。

## 业务与数据归属

| 范围 | 共享版负责实现 | Compose 基线处理 |
| --- | --- | --- |
| 引导、导航、主题与页面 | 共享 ArkTS 页面；平台差异集中在适配层 | 保留，作为迁移前行为的参照 |
| 聊天与流式请求 | 原始 ArkTS 协议/解析、会话 JSON、取消与权限门控 | 旧 Room 数据不被共享版自动读取或修改 |
| 图库与画像 | ArkTS 管线、索引、云协议及本地文件 | 旧图库 Room 数据保留；OCR 引擎共用 |
| 工作流 | ArkTS 编辑/保存/索引；执行接口仍明确受限 | 原 Kotlin 执行器尚未抽取，不因模块整合而自动启用 |
| 配置与授权 | 共享包私有偏好、独立声明版本 | 原 DataStore 保留；不隐式继承授权或密钥 |
| OCR、TTS | 调用共用 Kotlin 能力；界面不伪造成功 | 调用同一库，保留自己的业务结果适配 |

同一应用内每类数据只有一个写入者。桥接只返回能力结果，不写入另一套图库、会话或配置。
共享前端负责把结果纳入自己的状态与存储，因此无需把旧 Room 和 ArkTS JSON 同时写两遍。

两个包仍分别为 `com.clawmate.app` 和 `com.clawmate.shared`。这是保留现有数据的迁移边界；
统一构建与原生实现不等于已经切换正式包名。生产切换时应另做有版本的导入/校验与回退，
不能把修改包名当作数据迁移。

## 平台接口约束

- 共享接口不携带手机厂商品牌分支；具体系统能力可以返回可用、初始化中、取消或失败。
- OCR 只接受本地图片，受限解码并在后台执行；空文本与失败分别返回，不替换为示例文本。
- TTS 以真实引擎初始化及回调驱动界面；切换会话、离开前台与销毁时停止并清理资源。
- 耗时接口必须可取消、限制并发并丢弃过期结果，不能阻塞 Android UI 线程。
- 键盘可用窗口由 Android `adjustResize` 统一管理；共享入口关闭 ArkUI 的二次避让，
  组件不再额外平移输入区。键盘高度观测仍用于收起悬浮导航和滚动跟随。
- ArkTS 与 Kotlin 间传递有版本的 JSON 结果，不传任意类实例，不通过桥接执行任意命令。

## 后续抽取边界

图片附件/相机、ASR、通知、GUI 执行器与本地推理继续按具体能力迁移，先验证再启用。
共享业务已具备的云客户端、推荐、索引与工作流解析不重新包装为一套 Kotlin 业务。
鸿蒙 HDS 材质无法直接使用时，Android 适配保留几何、颜色、图标、交互与安全区；
不把基础模糊宣称为鸿蒙系统材质。

## 验证

先运行共用能力单元检查、两版构建与 Compose 回归，再运行共享 ArkTS 编译、契约与真机检查。
精确命令、失败和结果写入 `MIGRATION_STATUS.md`；不以工程依赖声明代替运行证据。
