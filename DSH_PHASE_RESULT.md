## Scope delivered (Phase 24)

1. **Faithful Seedream HTTP contract** (`profile/avatar/data/generation/`):
   `AvatarGenerationClient` / `SeedreamAvatarProvider` port the exact wire body
   from `SeedreamAvatarProvider.ets` (`model`, `prompt`,
   `sequential_image_generation`, `response_format`, optional `output_format`
   suppressed for models containing `seedream-4-5`, `size`, `stream`, `watermark`,
   optional `image`) with `Content-Type: application/json` and
   `Authorization: Bearer <apiKey>`, over the existing OkHttp + kotlinx stack.
2. **Bounded + strict validation**: `AvatarUrlValidator` enforces absolute
   http/https + real host, rejects embedded credentials and blank/relative URLs;
   `AvatarProviderLimits` caps prompt length (12,000), generation response body
   (512 KB), base64 payload (8 MB) and decoded image bytes (4 MB). Generate and
   download failures surface typed `AvatarProviderException` reasons
   (NOT_READY / INVALID_ARGUMENT / HTTP / PARSE / UNSUPPORTED_IMAGE / DOWNLOAD /
   TIMEOUT / CANCELLED / INTERNAL) — never fabricated.
3. **Parse only a real image**: `SeedreamResponseParser` honours only the first
   `data[0].b64_json` / `data[0].url` string (trimmed), bounded base64 decode; a
   `url` result is downloaded only through a validated absolute http/https URL,
   with `Content-Type` + size gates (`AvatarUrlValidator.acceptedContentType`,
   `MAX_IMAGE_BYTES`).
4. **No network call when unconfigured**: `AvatarGenerationGate` derives the
   honest `NOT_CONFIGURED` / `PARTIALLY_CONFIGURED` / `READY` from the configured
   settings (base URL http/https + host, api key, model, size all present for
   `READY`). `generateAvatar()` backs out with a redacted error and **zero HTTP
   bytes** unless READY, a provider is wired, and the local profile reaches the
   20% completeness floor.
5. **Bounded prompt + explicit consent**: `buildAvatarGenerationPrompt` builds a
   deterministic, `MAX_PROMPT_LENGTH`-capped prompt from the local profile; the
   explicit 生成数字分身 tap is the recorded text-to-image consent (no photo used).
6. **Local asset result path**: real generated bytes are persisted via the
   existing app-private `AvatarAssetRepository.persistGeneratedImage` as a
   `seedream-<seq>` version record (provider `"seedream"`), newest-first, with
   the same bounded/validated rules as a user import (byte cap + actual image
   decode), then displayed via Coil. Version history + delete/clear preserved.
7. **Screen wiring + honest lifecycle**: `ProfileAvatarViewModel` injects an
   `AvatarProvider` (production = `SeedreamAvatarProvider.withDefaultClient()`),
   adds `generateAvatar()`, an `AvatarRunState` (`IDLE / RUNNING / SUCCESS /
   ERROR`) and `generationError` (redacted, key-scrubbed). The 数字分身 screen
   shows `NOT_CONFIGURED`/`READY` capability plus `READY → RUNNING → SUCCESS /
   ERROR`; the button is disabled unless READY and not already running.
8. **Redacted errors / no secrets**: the api key is never logged, stored, or
   echoed; messages are scrubbed (exact key + `sk-*` pattern) before UI surfacing.
   No credentials added; the existing Settings fields
   (`avatarImageBaseUrl`, `avatarImageApiKey`, `avatarTextToImageModel`,
   `avatarImageSize`) already feed the config. No adb/hdc, no background
   generation (runs only from the explicit tap).
